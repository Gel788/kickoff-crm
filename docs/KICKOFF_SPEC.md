# KICKOFF — Техническое задание на продукт

**Продукт:** Kickoff — операционная платформа футбольных соревнований  
**Модель:** B2B — платит **только лига** (организация)  
**Видение:** От детского турнира до региональной/полупрофессиональной лиги — одна система: реестр, матчдень, протоколы, дисциплина  
**Версия:** 1.1  
**Дата:** 2026-05-21  
**Примечание:** тарифы и коммерция в этом документе **не описываются** — только продукт и автоматизация.

---

## 1. Краткое резюме

Kickoff — мультитенантный SaaS, где каждая **лига** (организация) ведёт полный цикл соревнования: реестр игроков, допуск, календарь, заявки на матч, live судейский и медицинский протокол, дисциплина, турнирная таблица, выгрузки уровня федерации.

**Это не CRM.** Kickoff = **операции соревнования + Matchday OS + integrity**.

**Варианты слогана:**
- *Здесь работает лига.*
- *От заявки до финального протокола.*

## 2. Цели и метрики успеха

| Цель | KPI (примеры) |
|------|----------------|
| Убрать Excel/WhatsApp с матчдена | 90%+ матчей закрыты в Kickoff |
| Ни одного нелегального состава на старте | 100% проверка допуска до lock |
| Протокол подписан за 2 ч после матча | Медиана: протокол → статус `closed` |
| Эффективность оператора лиги | −70% времени на регистрации vs ручной процесс |
| Внедрение | N лиг, M матчей/сезон, retention YoY |

---

## 3. Тенантность и модель доступа

### 3.1 Модель тенантов
- **Платформа** → много **организаций** (лига / ассоциация / оператор турнира)
- Изоляция данных по `organization_id`
- У каждой org: брендинг (лого, цвета), часовой пояс, язык по умолчанию, валюта

### 3.2 Кто платит (без тарифов)
- Платит **только лига** — один контракт на организацию.
- **Клубы, судьи, родители, делегаты** — бесплатный доступ внутри приглашённой лиги.
- Детали монетизации (пакеты, лимиты) — **отдельный документ позже**, не блокирует разработку.

---

## 3A. Видение: лига на автопилоте (масштаб продукта)

**Идея Kickoff:** оператор лиги не «ведёт Excel», а **настраивает регламент и подтверждает исключения**. Всё повторяемое делает система.

### Принцип «автомат vs человек»

| Сегодня в лигах (ручное) | Kickoff (автомат) | Человек только когда |
|--------------------------|-------------------|----------------------|
| Сводные таблицы в Excel | Таблица из событий протокола | Спорный результат |
| Письма «подайте заявку» | Дедлайны + пуши по ролям | Форс-мажор |
| Проверка допуска глазами | Движок eligibility | Апелляция / исключение |
| Жёлтые → бан в голове | Автобан в след. туре | Комитет отменил |
| Назначение судей в чате | Пул + правила + подсказки | Конфликт интересов |
| PDF протокола в Word | Генерация из live-данных | Редактура шаблона лиги |
| Переносы в мессенджере | Перенос → каскад уведомлений | Решение директората |

### Восемь слоёв автоматизации (дорожная карта продукта)

```text
[1] Реестр          → игрок допущен / заблокирован без ручной рутины
[2] Календарь       → матчи, переносы, конфликты арен
[3] Pre-match       → заявки, lock, проверки
[4] Matchday LIVE   → протокол, счёт, события
[5] Post-match      → закрытие, статистика, выгрузки
[6] Дисциплина     → санкции, апелляции, отбытие
[7] Медицина        → допуск, RTP, конфиденциальность
[8] Коммуникации    → все роли в нужный момент
        ↓
[9] Intelligence    → AI-календарь, аномалии, подсказки (позже)
```

### Слой 1 — Реестр и допуск (Eligibility Engine)

**Автомат:**
- Окна регистрации игрока (трансферные периоды по регламенту).
- Напоминание клубу: документ истекает через 14 / 7 / 1 день.
- Статус игрока: `допущен` только если все обязательные документы валидны.
- Дубликаты: предупреждение при похожем ФИО + ДР.
- При добавлении в заявочный лист сезона — проверка лимита squad size.
- Блокировка при активном бане / медотстранении без действия оператора.

**Ручное (осознанно):**
- Исключение «играет без документа» с обязательным комментарием и аудитом.
- Решение дисциплинарного комитета.

---

### Слой 2 — Календарь и логистика

**Автомат:**
- Генерация кругового календаря (дом/выезд, количество кругов).
- Статусы тура: «все матчи закрыты → тур завершён».
- Перенос матча → уведомление клубам, судьям, арене; сброс дедлайна заявки.
- Конфликт: один клуб — два матча в один слот → алерт оператору.
- Конфликт арены: два матча на одном стадионе.
- *(Фаза 4+)* AI-предложение слотов с учётом расстояний и еврокубков (если нужно).

**Ручное:**
- Утверждение нестандартного формата плей-офф.
- Принудительное назначение даты директором лиги.

---

### Слой 3 — Pre-match (заявки)

**Автомат:**
- Открытие окна заявки по расписанию (напр. −48 ч).
- Эскалация: −12 ч без подачи → пуш тренеру + админу клуба.
- Подача → мгновенная проверка eligibility по каждому игроку.
- Обе заявки поданы → очередь на утверждение оператору (или авто-утверждение если регламент разрешает).
- Дедлайн → **auto-lock**; поздняя подача = флаг `late_submission` + запись в дисциплину.
- Расхождение: игрок в протоколе не в заявке → критический флаг при старте live.

**Ручное:**
- Экстренная замена в заявке после lock (травма в разминке) — оператор лиги.

---

### Слой 4 — Matchday LIVE

**Автомат:**
- Старт матча судьёй → статус `live`, виджет счёта на сайт лиги.
- Гол → счёт, автор, ассист, таблица бомбардиров (после close).
- Карточка → запись в дисциплину, превью будущего бана.
- Замена → контроль лимита замен по регламенту.
- Конец матча → `finished`, напоминание подписать протокол.
- Офлайн PWA судьи → синхронизация с разрешением конфликтов (server wins / manual merge).

**Ручное:**
- Отмена события (ошибка) — с аудитом, не удаление из истории.

---

### Слой 5 — Post-match

**Автомат:**
- PDF судейского протокола сразу после `complete`.
- Если нет спора в течение N часов → матч в `protocol_review` → оператору чек-лист из 5 пунктов.
- `closed` → пересчёт таблицы, формы (последние 5), fair play, статистика игроков.
- Архив сезона: пакет матчей тура для федерации (ZIP/PDF).

**Ручное:**
- Оспаривание результата клубом.
- Переоткрытие матча (суперправо).

---

### Слой 6 — Дисциплина (Integrity Automation)

**Автомат:**
- 3 жёлтые → бан 1 матч (настраивается в регламенте).
- Красная → бан N матчей.
- При открытии заявки на след. матч — игрок с активным баном **не выбирается** (серый, причина).
- Создание дисциплинарного дела из события протокола.
- Таймер апелляции: если не подана — санкция в силе.

**Ручное:**
- Комитет: увеличить/снять санкцию, штраф клубу.

---

### Слой 7 — Медицина

**Автомат:**
- Нет меддопуска → блок в заявке (как eligibility).
- Травма в матче → связь с минутой в протоколе.
- RTP-протокол: статус «нельзя играть до даты X» → автоблок.
- Напоминание врачу клуба: незакрытый медпротокол после матча.

**Ручное:**
- Медицинское заключение в спорных случаях.

---

### Слой 8 — Коммуникации (Notification Hub)

**Автомат по ролям:**

| Событие | Лига | Клуб | Судья | Врач | Делегат |
|---------|------|------|-------|------|---------|
| Дедлайн заявки | сводка | пуш | — | — | — |
| Заявка отклонена | — | пуш | — | — | — |
| Назначение на матч | — | — | пуш | — | — |
| Матч live | дашборд | опционально | — | — | — |
| Протокол на подпись | — | — | — | — | пуш |
| Документ истекает | дашборд | пуш | — | — | — |
| Бан игрока | — | пуш | — | — | — |

Каналы: in-app → email → Telegram (фаза 2) → SMS (enterprise).

---

### Слой 9 — Intelligence (после стабильного ядра)

Не «магия ради хайпа», а конкретная польза лиге:

- **Аномалии:** клуб стабильно опаздывает с заявками; судья с паттерном спорных решений (для отчёта, не обвинение).
- **Умный календарь:** предложить перенос при погоде/праздниках (интеграция погоды).
- **Подсказка состава:** «игрок X на грани дисквалификации» — клуб видит до подачи.
- **Генерация превью-отчёта тура** для пресс-службы лиги после закрытия тура.

### Масштаб: одна платформа — все типы лиг

| Тип лиги | Что включаем в конфиг регламента |
|----------|----------------------------------|
| Детская U7–U18 | Опекуны, согласия, укороченные таймы, safeguarding |
| Любительская взрослая | Простой протокол, мягкие дедлайны |
| Региональная | Полный дисциплинарный контур, судейский пул |
| Полупрофи | Легионеры, лицензии клубов, FIFA ID |
| Турнир на выходные | Укороченный сезон, быстрый плей-офф |

**Не отдельные продукты** — один Kickoff, **профиль регламента** на сезон.

---

### Что ещё «додумаем» (бэклог идей — без привязки к фазе)

- **Стадионы и аренды:** бронь слота, акт приёма поля.
- **Судейская коллегия:** экзамены, категории, рейтинг после матча (оценка делегата).
- **VAR-lite:** поле решения VAR в событии без видеоцентра.
- **Финансы лиги:** штрафы из дисциплины → счёт клубу (не тарифы Kickoff, а учёт лиги).
- **Скаутинг / реестр талантов** (дети): только с согласия родителя.
- **Интеграция с сайтом лиги:** виджет таблицы, календаря, live.
- **Мультисезонная история игрока** внутри org.
- **Сублиги / фарм** — связь клуб А ↔ клуб Б (дубль не играет против основы).
- **Техническое поражение / неявка** — автомат из статуса заявки/явки.
- **Fair Play коэффициент** в таблице (опционально).
- **Экспорт в федерацию** одной кнопкой за тур.

*Список живой — дополняем по пилотным лигам.*

## 4. Роли и права (RBAC)

Права **в контексте:** `organization` + опционально `club_id` + опционально `match_id`.

| Роль | Код | Область |
|------|-----|---------|
| Суперадмин платформы | `platform_admin` | Все org (только команда Kickoff) |
| Владелец лиги | `league_owner` | Вся org |
| Оператор лиги | `league_operator` | Календарь, утверждение заявок, закрытие матча |
| Дисциплинарный комитет | `disciplinary` | Санкции, апелляции |
| Админ клуба | `club_admin` | Один клуб |
| Тренер клуба | `club_coach` | Черновики заявок, протоколы read-only |
| Делегат клуба | `club_delegate` | Подписи на матче, споры |
| Главный судья | `referee_chief` | Назначенные матчи — полный протокол |
| Помощник судьи | `referee_assistant` | Ограниченный ввод событий по конфигу |
| Врач лиги | `medical_league` | Все матчи — медмодуль |
| Врач клуба | `medical_club` | Свои игроки — ограниченный доступ к PHI |
| Назначающий судей | `referee_assigner` | Только назначения |
| Статистик | `statistician` | Только закрытые матчи |
| Родитель / опекун | `guardian` | Только связанные несовершеннолетние — фаза 1b |

**Правила:**
- Один пользователь → несколько ролей в разных клубах/org
- Несовершеннолетние: без опекуна логин запрещён (порог возраста в настройках, по умолчанию 16)
- Медданные (PHI): ACL на уровне полей

- Backend: Node.js (NestJS) или Python (FastAPI)
- БД: PostgreSQL 16+
- Кэш/очередь: Redis + BullMQ / Celery
- Frontend: Next.js 14+ (App Router)
- Приложение судьи: PWA (тот же репо, маршрут `/referee`)
- Auth: JWT access + refresh, OAuth позже
- Файлы: S3-совместимое (MinIO в dev)
- Realtime: WebSocket для live-счёта (фаза 1b)

# ФАЗА 1 — MVP «лига проводит сезон» (месяцы 1–3)

**Цель:** Одна пилотная лига проходит сезон без Excel на ядре матчдена.

## 1.1 Реестр

| ID | Функция | Детали |
|----|---------|--------|
| R-01 | Создать сезон | Даты, статусы черновик/активен/архив |
| R-02 | Соревнование + дивизион | Название, круговой формат |
| R-03 | Зарегистрировать клубы | Название, короткое имя, цвета, домашняя арена |
| R-04 | Карточка игрока | ФИО, ДР, фото, гражданство, категория |
| R-05 | Привязка игрока к клубу/сезону | Номер, позиция, статус |
| R-06 | Документы игрока | Загрузка скана, тип, срок действия |
| R-07 | Допуск вручную | Оператор: допущен / отстранён / на проверке |
| R-08 | Заявочный лист клуба на сезон | Макс. N игроков по регламенту |
| R-09 | Поиск/фильтр игроков | По клубу, статусу, имени |

**Бизнес-правила:**
- Предупреждение о дубликате игрока в org (ДР + имя, fuzzy)
- В заявку на матч нельзя добавить `suspended` или `pending`

## 1.2 Календарь

| ID | Функция | Детали |
|----|---------|--------|
| C-01 | Создать туры | Номер тура, даты |
| C-02 | Создать матчи | Хозяева/гости, дата/время, стадион |
| C-03 | Статусы матча | scheduled → open_squads → squads_locked → live → finished → protocol_review → closed |
| C-04 | Перенос матча | Новая дата + причина + аудит |
| C-05 | Виды календаря | Сетка лиги, фильтр по клубу |

## 1.3 Движок регламента (v1 — простой)

| ID | Функция | Детали |
|----|---------|--------|

## 9. Жизненный цикл матча (стейт-машина)

```
scheduled (запланирован)
    → squads_open (окно заявок)
    → squads_submitted (обе подали или тех.поражение)
    → squads_approved (лига утвердила)
    → squads_locked (заблокировано)
    → live (судья начал)
    → finished (судья завершил)
    → protocol_review (лига проверяет)
    → closed (таблица зафиксирована)
    → disputed (ветка из protocol_review)
```

**Условия перехода:**
- `live` только при squads_locked + назначен судья
- `closed` только при подписанном протоколе + нет критических флагов

## 13. Соглашения API (REST v1)

- База: `/api/v1/organizations/:orgId/...`
- Пагинация: `?page=&limit=`
- Ошибки: RFC 7807 problem+json
- Идемпотентность: заголовок `Idempotency-Key` на POST заявки и событий
